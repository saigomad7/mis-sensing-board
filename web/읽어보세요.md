# 화면 — rev07 시안을 실제로 붙인 것

```bash
python web/server.py          # → http://127.0.0.1:8700
```

`pip install` 이 필요 없다. **표준 라이브러리만** 쓴다(폐쇄망 대비).

## 무엇이 시안과 같고 무엇이 달라졌나

**같은 것** — 색·짜임을 그대로 옮겼다. 흰 바탕 · 얇은 테두리 · 주황 강조 · 큰 모서리.
상단바 · KPI 4칸 · 축 카드(펼침/접힘) · `시장·전망·사내·논의` 행 · 출처 칩 · 하단 질문칸.

**달라진 것** — **실제로 돈다.**

| 시안 | 지금 |
|---|---|
| 고정된 예시 글 | 검색 결과를 그때그때 채운다 |
| 축이 그림 | `server.py` 의 `AXES` 에서 정한다 |
| 권한 표시 없음 | 상단에서 바꾸면 **화면의 행이 실제로 달라진다** |
| `[시안 · 실제 동작 아님]` | 근거·점수·출처가 전부 진짜 |

## 로직이 여기 없다

`server.py` 가 **노트북(`pipeline_step_by_step.py`)을 그대로 불러** 그 함수를 쓴다.

```python
NB = runpy.run_path("pipeline_step_by_step.py")   # 출력은 삼킨다
search, evidence_block, verify = NB["search"], NB["evidence_block"], NB["verify"]
```

**화면과 노트북이 같은 코드를 본다.** 노트북에서 정규화·조각 규칙을 고치면
서버를 다시 띄우는 것만으로 화면에 반영된다. 불러오는 동안 `run_once()` 가 돌아
**새 문서가 있으면 자동으로 적재된다.**

## 화면의 행 = 자료 유형

| 행 | 유형 | 뜻 |
|---|---|---|
| 시장 | `news` `official` `filing` | 밖에서 무슨 일이 |
| 전망 | `report` `research` | 시장은 어떻게 보나 |
| 기준 | `external_doc` | 정해진 규격·통계 |
| 사내 | `internal_doc` | 우리는 어떤 상태인가 |
| 논의 | `mail` | 최근 어떤 이야기가 |

## 마켓 센싱으로 쓰려고 넣은 넷

| # | 무엇 | 왜 |
|---|---|---|
| ① | **점수 하한** (`CAT_FLOOR=0.55`) | 빈칸을 억지로 채우면 없는 이야기를 지어낸다. 미달이면 카테고리를 통째로 뺀다 |
| ② | **지난 기록과 대조** (`briefs` 표) | 마켓 센싱의 핵심은 "지금 무엇이 있나" 가 아니라 **"무엇이 달라졌나"** |
| ③ | **축은 요약이 아니라 판단** | 사내↔외부가 **어긋나는 곳**을 먼저 짚게 한다 |
| ④ | **변화 큰 축이 위로** | 임원이 스크롤하지 않게 |

**중복도 함께 정리했다** — 해석(뉴스·리포트·기관)은 한 축에서만,
사실(사내문서·공시·기업공식)은 여러 축에서 근거가 되므로 중복을 허용한다.

### 실측 — 하한을 걸었더니

```
축1 HBM        근거 9 → 5  (제외 4)
축4 공정·표준   근거 9 → 1  (제외 6 · 중복 2)   ← 정직하게 1건
축3 DRAM       근거 9 → 3  (제외 5 · 중복 1)
```

축4는 **JEDEC 표준 하나뿐인 게 사실**이다. 전에는 무관한 사내문서·메일로 채웠다.

**노트북에서 셀을 돌려 확인한 것이 곧 화면에 나오는 것이다.**

### 한 줄이 만들어지는 순서

```
축 (HBM)
 ├ 검색 12건
 ├ 카테고리로 나눔 — 시장 3 · 전망 3 · 기준 2 · 사내 2 · 논의 1
 ├ 카테고리마다 조각을 **묶어서** 모델에 한 번에 넘김
 └ 카테고리별 한 줄 + 축 전체 한 줄을 받음
```

**축 하나당 모델을 한 번만 부른다.** 카테고리마다 따로 부르면
축 5개 × 카테고리 5개 = 25번이 된다. 묶어 물으면 5번으로 끝난다.
지난 기록 대조도 같은 호출에 얹으므로 **회차가 늘어도 5번**이다.

★**축 요약은 카테고리 요약을 다시 요약한 것이 아니다.**
  같은 호출에서 **원문 청크를 보고** 카테고리 줄과 축 줄을 함께 받는다.
  두 번 압축하면 밋밋해지고, 특히 사내↔외부 충돌은 원문을 봐야 잡힌다.

**행을 누르면** 그 요약이 어떤 근거에서 나왔는지 점수와 함께 펼쳐진다.
요약이 이상하면 바로 원문을 확인할 수 있다.

**모델이 없으면** 요약 대신 첫 조각을 잘라 쓰고 화면에 `요약 아님` 을 표시한다.

## 주제축을 바꾸려면

`server.py` 의 `AXES` 하나만 고친다.

```python
AXES = [
    {"no": 1, "name": "HBM · 고대역폭 메모리", "q": "HBM4 수율과 양산 일정"},
    ...
]
```

`q` 가 **그 축을 대표하는 질문**이다. 검색이 이 문장으로 돈다.

## 창구

| 주소 | 무엇 |
|---|---|
| `/` | 화면 |
| `/api/brief?access=부서` | 축별 브리핑 |
| `/api/ask?q=질문&access=부서` | 질문 하나 |
| `/api/sync` | 새 문서 적재(`run_once`) |

## 실측

```
브리핑 5개 축   191ms   (조각 36개 · 가짜 벡터)
질문 하나        36ms
```

권한을 바꾸면 실제로 달라진다 —

```
전사 → 1번 축 근거 6건 · 행 [전망, 기준]
부서 → 1번 축 근거 8건 · 행 [전망, 기준, 사내, 논의]
```

## 모델이 붙기 전과 후

**지금(가짜 벡터)** — 화면 하단에 경고가 뜬다. 흐름은 전부 확인되지만 순위는 믿으면 안 된다.
축 요약은 1위 근거의 첫 줄을 줄여서 쓴다.

**모델을 붙이면** — 순위가 제대로 나오고, 축 요약을 생성 모델이 한 문장으로 만든다.
질문 화면에는 답변과 **검증 결과 3개**가 함께 뜬다.

`.env` 만 채우면 된다. 코드는 손대지 않는다.
